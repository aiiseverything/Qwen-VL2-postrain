## 1. 数据规模与 token 数

### 1.1 样本数（实测）

| 数据集 | 文件 | 条数 | 来源构成 |
|---|---|---|---|
| SFT | `data/processed/sft_400k.clean.jsonl` | **399,642** | llava665k 296,590 / sharegpt4v 50,012 / **videoinstruct 53,398** |
| DPO | `data/processed/dpo_10k.jsonl` | 5,731 | rlhf-v |
| RLVR | `data/processed/rlvr/*.parquet` | 25,748 | geometry3k 2,101 + geoqa 8,031 + MMK12 15,616 |

**视频数据的变化**（2026-09-26 重建）：

| | 重建前 | 重建后 |
|---|---|---|
| 视频片段 | 3,906 | **7,246** |
| SFT 视频样本 | 28,298 | **53,398** |
| 视频占比 | 7.1% | **13.4%** |

> 占比 13.4% 已超过 PLAN §7.1 原定的 11.7%（video 35K / 300K）。
> 提升来自修复 yt-dlp 格式选择器过窄的问题（见 `docs/05` P34：失败率 50% → 0.3%）。

**质量过滤**：输入 399,775 → 输出 399,642，过滤掉 133 条
（其中去污染命中 143 条 —— 与 MME/MathVista 评测图像重叠，见 `quality_filter_stats.json`）。

### 1.2 Token 数（**实测**）

> **计量口径**：由 `scripts/training/measure_tokens.py` 实测得出，**非字符数估算**。
> - 文本 token：用 `Qwen2VLProcessor` 的 tokenizer **真实编码**
> - 视觉 token：调用**训练时用的同一个 image_processor**，读 `image_grid_thw` 反推
> - 抽样 8,000 条（种子 42），原始结果存 `docs/training/tokens_sft_400k.clean.json`

| 项 | 均值 | 中位 | P95 | 最大 |
|---|---|---|---|---|
| **文本 token / 样本** | **175** | 138 | 419 | 918 |
| **视觉 token / 样本** | **285** | 308 | 323 | 330 |
| **合计 token / 样本** | **460.1** | — | — | — |

**分来源明细**（抽样 8,000 条中：含图像 6,916、含视频 1,084）：

| 来源 | 条数 | 文本 tok/条 | 视觉 tok/条 |
|---|---|---|---|
| llava665k | 5,922 | 188 | 282 |
| sharegpt4v | 994 | 205 | 298 |
| videoinstruct | 1,084 | 79 | 288 |

> 注意 **videoinstruct 的文本明显更短**（79 vs 188）——视频样本的问答本来就简短，
> 且视觉 token（288）与图像样本（282）相当，说明 `video_maxlen=32` 的约束生效了。

**★ 全量推算**（399,642 条 × 实测均值）：

| 项 | 单 epoch | 2 epoch |
|---|---|---|
| 文本 token | ≈ 70.0 M | ≈ 139.9 M |
| 视觉 token | ≈ 113.9 M | ≈ 227.8 M |
| **合计** | **≈ 183.9 M** | **≈ 367.7 M** |

> ⚠️ 这是**按抽样均值外推**的估计（抽样 8,000/399,642 ≈ 2%）。
> 训练结束后以 `trainer_state.json` 里的实际计数为准，届时回填。

**关键约束参数**（这两个直接决定 token 数，见 `docs/02`）：

```yaml
image_max_pixels: 262144    # 512×512 → 实测视觉 token 最大 330, 中位 308
image_min_pixels: 1024
video_max_pixels: 16384
video_fps: 2.0
video_maxlen: 32            # ★ P25: 上限 32 帧 (默认 128 会撑爆 cutoff_len)
                            #   实测视频样本视觉 token 均值 288
cutoff_len: 4096            # 单样本最大 token 数 (超长样本被丢弃而非截断)
```

> 实测视觉 token 上限 330 与 `image_max_pixels=262144` 的理论值（512×512 → 约 324）
> 吻合，说明该参数**确实生效了**。

### 4.2 RL 的 token 消耗（这是 RL 与 SFT 最大的不同）

RL 的 token 消耗分三块，**必须分开记**：

| 部分 | 计算方式 | 值 |
|---|---|---|
| **Rollout 生成** | prompts × n(5) × 平均 response 长度 | 待实测 |
| **Actor 前向+反向** | (prompt + response) × 采样数 | 待实测 |
| **Reference 前向** | (prompt + response) × 采样数 | 待实测 |
| **总计** | — | 待实测 |

> ⚠️ RL 的 token 消耗通常是 SFT 的**数倍**（每个 prompt 要采 5 条、还要过 ref 模型），
> 所以这里不能只记「样本数 × 长度」。

## 6. 全局约定

### 6.1 视觉 token 计算规则（Qwen2-VL）

```
视觉 token 数 = (H_patch × W_patch) / merge_size²
其中 patch 尺寸 14px，merge_size = 2
图像被 smart_resize 到不超过 image_max_pixels (262144 = 512×512)
视频每帧不超过 video_max_pixels (16384)，最多 video_maxlen (32) 帧
```

### 6.2 loss mask

整段序列送入模型，但 **loss 只对 assistant 的回答计**，user 提问部分被 mask。
由 `template: qwen2_vl` + 数据里的 `role` 标签决定。

### 6.3 冻结策略

- ViT (`freeze_vision_tower: true`)：**冻结**（R6 要求）
- merger/projector (`freeze_multi_modal_projector: false`)：**可训练**（D3）
- 可训练参数 ≈ 1.5B（占 2.209B 的 68%）

### 6.4 随机种子

- 数据抽取：`SEED = 42`（`scripts/prepare/to_sharegpt.py`）
- DPO 构建：`SEED = 42`
- 训练框架默认种子（LLaMA-Factory / EasyR1 各自默认）

### 6.5 复现所需的最小信息集

```bash
git 仓库: /home/ml-user/workdir/project-2
模型:     models/Qwen2-VL-2B-Instruct
SFT:      configs/sft_qwen2vl_2b_7gpu.yaml    + data/processed/sft_400k.clean.jsonl
```
