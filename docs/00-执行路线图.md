## 2. 各阶段 go / no-go 判据

**每一步都有一个「该不该继续」的判断点。不满足就别往下走。**

| 阶段 | 判据 | 不满足时查什么 |
|---|---|---|
| 图像解压后 | 各前缀图像数 > 0，且 = 标注中该前缀的条数量级 | 看 `stats_report.md` 丢弃明细；前缀目录名对不对 |
| SFT 抽取后 | 产出 ≥ 350K（目标 400K，缺口有解释） | 哪些前缀被大面积跳过；图像路径映射 |
| 去污染后 | 报告里**明确写了**剔除数，或明确写了「未生效」 | `eval_fingerprints` 是否为 0 |
| SFT 前 100 step | 显存占用可解释；loss 平滑下降；无 NaN | 降 `image_max_pixels`；降 lr |
| SFT 收敛 | loss 到 0.5–1.0 区间并趋平 | lr 太大/太小；数据是否含大量噪声 |
| **GRPO 开跑 5 步内** | **reward 均值 > 0 且方差 > 0** | ★ 立刻停：答案列名/格式（`docs/02` B1） |
| GRPO 收敛 | reward 曲线上升后趋平；`rewards/accuracies` 稳定在 0.3–0.8 | 任务太难/太易；kl_coef 太大 |
| 评测后 | SFT 相对 pretrained 在 MME/MathVista 上有**可解释的**变化 | prompt 模板是否四个模型一致 |

### 关于「涨分」的预期管理

- **MME / MathVista**：SFT 后应上升（这两者有对应的图像训练数据）。
- **Video-MME**：**若 SFT 未含视频数据，预期持平或下降**。
  这是诚实发现，不是失败（PLAN D6 / K4）。
- **DPO 主要降幻觉**，不保证涨 benchmark 分。若 DPO 后分数略降但输出更可靠，
  这也是正常结果 —— 所以评测矩阵里保留 DPO 一列（PLAN A4）。

## 4. 失败回退路径

| 卡在哪 | 先试 | 再试 | 最后手段 |
|---|---|---|---|
| 图像前缀匹配不上 | 检查解压后目录结构 | 改 `common.py` 的 `IMAGE_PREFIX_TO_DIR` | 放弃该前缀，从其它来源补足配额 |
| 视频可用率过低 | 换 `--max-height` / 加 JS runtime | 放宽到 <5 分钟 | 放弃视频，改纯图像 SFT 并如实报告 |
| GRPO reward 恒 0 | 打印几条 (pred, gold) 人工看 | 检查是否取错列（`solution` vs `answer`） | 换 geometry3k 冒烟确认管线 |
| Qwen2-VL 在 EasyR1 上跑不通 | 用 geometry3k 冒烟 | 换官方 Docker 镜像 | **降级用 Qwen2.5-VL-3B 验证管线**（K3） |
| OOM | 降 `image_max_pixels` | 降 batch / 增 grad_accum | 开 ZeRO-3（但 PCIe 无 NVLink 会慢） |
| DPO 后模型崩坏 | lr 降到 5e-7 | 减 epoch | 用 LoRA 而非全参 |
